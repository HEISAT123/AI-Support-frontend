# AI Support

Фронтенд ИИ-ассистента службы поддержки на React, Vite, TypeScript и SCSS. Оператор анализирует обращения, открывает рекомендации, копирует черновик ответа и оценивает статьи. Руководитель смотрит сводку и динамику FCR за выбранный период.

## Локальный запуск

Нужен Node.js 22.12+. Запусти FastAPI на порту 8000 и выполни команды из корня проекта.

```powershell
cd frontend
npm ci
npm run dev
```

Открой адрес, который выводит Vite.

По умолчанию Vite проксирует `/api/v1` на `http://127.0.0.1:8000`. Другой адрес сервера можно задать в `.env.local`, скопировав `.env.example`. Для прямого подключения можно использовать полный URL в `VITE_API_BASE_URL`. В этом случае FastAPI должен разрешать запросы с адреса фронтенда, включая заголовок `X-Api-Key` для административных операций.

```powershell
npm run lint
npm run build
npm run preview
```

Для публикации раздай файлы из `dist` и настрой возврат `index.html` для маршрутов приложения. При относительном `VITE_API_BASE_URL` направь `/api/v1/*` на FastAPI. Административный ключ вводится по запросу в форме и передаётся только в заголовке соответствующего запроса.

## Интеграция с API

Маршруты и правила ошибок сверены с `backend doc.docx`. Полные JSON-схемы ответов и параметры списков в документе отсутствуют. Ниже приведены допущения фронтенда, которые нужно сверить с OpenAPI запущенного бэкенда. Преобразования можно править в `src/api`, а используемые интерфейсом типы находятся в `src/types/support.ts`.

| Маршрут | Данные, используемые фронтендом |
| --- | --- |
| `POST /requests/analyze` | Тело `{ text }`. Результат содержит `requestId` или `id`, `category`, `confidence`, `entities`, `suggestedReply`, `degraded` и `recommendations`. У рекомендации есть `articleId`, `title`, `category`, `snippet`, `relevance` и, при наличии, `body`, `helpful`. Все оценки релевантности в одном ответе используют общую шкалу. Сервер может указать `relevanceScale` со значением `fraction` (0–1) или `percent` (0–100). Без указания шкалы значение выше 1 означает проценты, остальные ответы считаются долями. |
| `GET /requests/{id}` | Та же форма результата с исходным текстом обращения. |
| `POST /requests/{id}/feedback` | Тело `{ articleId, helpful }`, где `helpful` — булево значение. |
| `GET /knowledge/articles` | Фильтры `q` и `category`. Ответ содержит массив статей или объект `{ items, total }`. Полный Markdown статьи берётся из поля `body` в списке, поскольку отдельный маршрут чтения статьи в контракте отсутствует. |
| `POST /knowledge/articles`, `PUT /knowledge/articles/{id}` | Тело `{ title, body, category, tags, isActive }`. |
| `DELETE /knowledge/articles/{id}` | Деактивация статьи. |
| `POST /knowledge/import` | Тело `{ articles: [...] }`. В интерфейс загружается JSON-файл с массивом статей. |
| `GET /analytics/summary` | `from`, `to` в формате `YYYY-MM-DD`, необязательные `category` и `groupBy` (`day` или `week`). Сводка поддерживает `totalRequests`, `fcr` в процентах, `averageHandlingSeconds`, `helpfulRate` в процентах, `byCategory`, `series` и `topQueries`. |

Расчёт FCR выполняется на бэкенде по обратной связи и факту повторного открытия обращения. График отображает ряд из API. Если сервер не прислал показатель, интерфейс покажет прочерк или пустое состояние.

Недавние обращения доступны в пределах открытого сеанса. Профиль и настройки хранятся в браузере. Серверная авторизация и персональные показатели в контракте API отсутствуют.

## Структура

- `src/app` — маршруты и глобальные стили.
- `src/components/pages` — страницы со своими SCSS-модулями и `index.ts`.
- `src/components/widgets` — оболочка, кнопки оценки и общие элементы интерфейса.
- `src/components/popup` — модальные окна управления статьями.
- `src/api`, `src/context`, `src/hooks`, `src/lib`, `src/types` — запросы, состояние, хуки, вспомогательные функции и типы.
